1. How this review was done

Every file in the repository was opened and read. Every data file was parsed and its

contents compared against the official page it claims to come from. Where a value in the

repository could be traced to an official page and matched, it is marked verified. Where

it could be traced but did not match, or where the claimed source does not publish that

value, it is marked unverified and listed in §4. Nothing was inferred to fill a gap.

Official hosts used for verification:

  • https://www.nba.com/games?date=YYYY-MM-DD — final scores, game IDs, tip times, printed records
  • https://www.nba.com/standings — official wins and losses
  • https://official.nba.com/nba-injury-report-2026-27-season/ — injury report index and reporting policy
  • https://www.nba.com/stats/players/traditional — player season averages (partially readable)

Sources that could not be re-read and are therefore treated as unverifiable this session:

stats.nba.com JSON endpoints (blocked), and all NBA.com Stats HTML tables (rendered

client-side; only page chrome is returned). This is an environment limitation, not a claim

that the earlier captures were wrong — but it does mean nothing in this build may depend on

them.

3. What this review confirms is sound

1. Source discipline. Every data file carries a source_url or src_* field pointing at

an official host. No file cites a non-official source as if it were official. This is the

single most important property of the repository and it holds throughout.

2. Honest self-labelling. Three separate places label their own output as not valid

(backtest.json "CONTAMINATED", derived/lines.json props "BLOCKED",

originated_lines.json "all parameters are this project's assumptions"). A reviewer can

tell what is a measurement and what is an assumption without reading the code.

3. Correlation discipline. derived/correlations.json separates what was measured from

what was derived from marginals from what cannot be computed at all. Most projects blur

these three. This one does not.

4. No fabricated results. Across both prior builds, no strategy is reported as validated.

Given the sample sizes available, that is the correct answer.

4. Irregularities

Severity: High = a published number could mislead; Medium = a limitation that must be

stated; Low = housekeeping.

R1 — High — 23 games are published by NBA.com as fixtures with no score

?date=2026-10-24 (8 games, IDs 0022600104–0022600111) and ?date=2026-11-02

(15 games, IDs 0022600158–0022600172) render as FINAL with a dash in every score, record

and leader cell, and with no HIDE SCORES / HIDE ODDS toggles present. Reproduced twice,

40 minutes apart, across every chunk. Link:

?date=2026-10-24 ·

?date=2026-11-02.

These 23 results are determinable from the official standings residual (see R3) but are

not published, so this project records them as fixtures with blank scores. Any other

project filling them in from the standings would be inferring an official value, which this

project does not do. Cross-references F1.

R2 — Medium — five or more parallel builds now occupy one repository, most of them reachable

At 2f44c98 there was a dated-snapshot build at the repository root and in docs/, and a

second build under docs/b/. pages.yml deploys from the repository root, so the root build

is what the public URL serves. While this review was being written, main advanced 91 commits

across at least six further sessions, adding command-center/, integration/, desk*.html,

verification.html and schedule-verified.html to the same root.

This is the single biggest risk in the repository: several sessions are writing the same paths

with different numbers, and nothing arbitrates between them. **This build therefore claims one

namespace, origination/, and leaves the root exactly as it found it.** An earlier draft that

moved the root pages to archive/build-a/ was reverted, because those files are owned by

sessions whose pull requests are still open. See suggestion G10.

R3 — Medium (positive finding, recorded for audit) — the game log reconciles exactly

151 captured final scores plus the 23 unpublished fixtures = 174 games, which equals the sum

of official wins across all 30 teams on

the standings page. Per-team game counts reconstructed from

the log match the standings for all 30 teams. This is the strongest available evidence that

the log is complete and correctly oriented, and it is the anchor for every number on the new

site.

R4 — High — no market odds exist from any official source

data/strategies.json gates G4 (beat a no-skill baseline) and G5 (closing-line value) are

marked Blocked, correctly. No official NBA property publishes betting prices. Every "ROI"

anywhere in this repository — in either build — is therefore ROI against our own price,

not against a market. Cross-references F2.

R5 — High — injury impact is modelled with assumed constants, and the output rows do not say so

data/derived/injury_impact.json and scripts/injury_impact.py apply a

status → probability of playing mapping (Out 0.00, Doubtful 0.25, Questionable 0.50,

Probable 0.80, Available 1.00) and a production_transfer of 0.55, redistributing minutes

proportionally to teammates' existing minutes. None of those five numbers appears on any

official page. The sensitivity table shows how much they matter: for GSW@SAS the originated

spread moves from 13.3 to 18.9 points as production_transfer goes 0.35 → 0.55. That is a

6.6-point swing driven entirely by an invented parameter. This build therefore applies

no injury adjustment to any originated line and states that on the lines page.

Cross-references F8.

R6 — High — player production is not available in game-by-game form

The only player data in the repository is two partial season-average leaderboards: 50 players

by scoring and 24 by minutes, out of 465. Neither is a game log. A prop line is a point on a

distribution, and a season average says nothing about the shape of that distribution, so no

prop line can be originated honestly. Both prior builds correctly mark props as blocked.

Cross-references F3.

R7 — Medium — parlay joint probabilities are bounds, not measurements

data/originated_lines.json parlays carry joint_lb and joint_ub computed from the

marginals via Fréchet–Hoeffding bounds — for example a two-leg parlay at p1 = 0.838,

p2 = 0.747 gives a joint between 0.585 and 0.747, i.e. fair odds anywhere from 1.34 to 1.71.

That is a correct and honest computation, but the range is wide enough to be unpriceable.

This build measures the joint directly instead; see the correlations page. Cross-references

F9.

R8 — Medium — the Build A backtest is contaminated, and says so

data/derived/backtest.json reports MAE 14.06 on totals and 12.36 on margin over 14 games,

and labels itself "CONTAMINATED — inputs are season-to-date and include the tested games",

with the verdict "NOT VALIDATION. Look-ahead bias is present". Correctly labelled. This build

replaces it with a walk-forward backtest in which every forecast is fitted only on strictly

earlier games (G5, mechanically enforced).

R9 — Low — the scheduled refresh has never run

.github/workflows/refresh-data.yml is scheduled but engine/fetch_official.py cannot reach

the network from this sandbox, and the workflow has no recorded successful run. Every figure

on the new site is from a single manual capture at 2026-11-14 00:42 UTC. Cross-references F7.

R10 — Low — roster/leader attributions that look like errors but are not

The captured leader tables attribute Anthony Davis to WAS, Giannis Antetokounmpo to MIA,

LaMelo Ball to MIN, Naz Reid to CHA, Darius Garland to LAC, Paul George to PHI, Kevin Durant

to HOU and Damian Lillard to POR. These come from official pages as captured and are recorded

as captured; they are not corrected, because correcting them would be an inference. Flagged

for a human to sanity-check against the actual roster pages. Cross-references F11.

R11 — Low — a neutral-site game is mixed into the home/away log

2026-11-07 DEN@IND was played in Mexico City. The model zeroes home-court advantage for it.

Cross-references F12.

R12 — Medium — this build deliberately does not own the root

The root build's pages (lines.html, gameflow.html, sources.html and so on) sit at the

same paths GitHub Pages serves from, and other sessions are editing them right now. Rather

than displace them, this build publishes under origination/ and touches no shared path.

The cost is that the public landing page at /NBA1/ is not this build; the benefit is that

nothing here can break another session's site. Resolving that is a coordination decision,

not a technical one — see suggestion G10.

5. What this build changes

  • Replaces both prior backtests with one walk-forward evaluation over 101 out-of-sample games.
  • Replaces assumed injury adjustments with no adjustment at all, and says so.
  • Replaces parlay bounds with a measured joint probability and a measured same-slate

    • correlation.

  • Adds a Monte-Carlo null for every strategy and a statistical power calculation for every

    • signal, so that "not significant" is distinguished from "not enough data".

  • Publishes a 12-item flagged register, a 14-item question register split by known/unknown,

    • and a 12-item ranked suggestions list.

  • Publishes under origination/ and leaves every shared path untouched, so that it can be

    • merged without displacing any other session's root build.
