Why a declaration exists, and what it does not do

The gate used to require data/raw/standings.json, team_traditional.json and team_opponent.json. Those files have zero commits in the repository's history because the three official pages render their tables client-side — the runner's own evidence records measure 0 <tr> rows on the standings page and 0 /stats/team/ links on the traditional page. A requirement no run can satisfy does not make the site safer; it makes the rebuild step dead code, which is what it had been since gate commit 25bfcea (2026-11-15T11:38Z) landed after the last successful rebuild at 12:43:11Z that same day.

data/raw/unreadable_sources.json declares those three sources unreadable with their evidence and a hard expiry (currently S10_team_opponent, S8_standings, S9_team_traditional). A declaration never promotes a value and never touches an input the model loads: none of the three is consumed by engine/pipeline.py. It is refused the moment the page starts parsing rows, the moment it expires, and the moment the source is not fetched at HTTP 200 in the same run.
