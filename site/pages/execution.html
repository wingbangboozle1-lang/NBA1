C. How to review a suggestion and choose a path

A list of ideas is not a decision. This section makes every option reviewable on the same four questions, and it defines the gate a change must pass before anyone builds it.

  1. What does it change, in one sentence? — If the sentence needs an 'and', it is two suggestions. Split it.
  2. What must be true first? — The dependency. Most options here are blocked on a missing official input, not on effort. An option whose dependency is unmet is 'not ready', not 'low priority'.
  3. What is the smallest test that would tell you it worked? — Not the full build - the cheapest measurement that moves the answer. Every row below names one.
  4. What does it cost you if it is wrong? — Risk stated as the thing that breaks, not as a rating.
Acceptance gate — a change must pass all five before it is built
  1. The change is additive: a new file or a new column. Nothing already published is overwritten, so the audit trail survives.
  2. The change can be re-derived from an official source by someone who has not read the code. If it cannot, it is a model assumption and must be declared as one.
  3. The change has a stated failure condition - a number that would prove it wrong - written down BEFORE it is run.
  4. The change does not move a published line, pick or gate result without the owner saying so explicitly on this page first.
  5. The change leaves the verification suite green: check_site.py, check_links.py, verify_all.py, render_check.mjs and the broken-link scan.

Read the three sections in this order. Section A closes a missing official input - none of it is optional for a real edge and all of it is blocked on sources that do not exist in a usable form yet. Section B is about decision quality on the site itself and is cheap. Section C is model work that should not start until Section A has landed. Then, for any option you pick, fill the four questions and the gate above on the Flagged for Review page so the next session inherits a decision rather than an opinion.

E. What would have to be true for this project to claim a real edge

Stated once, plainly, so no page has to imply it.

  • A price. No NBA-operated source publishes a closing price, so every figure here is model against a naive reference model. Without a licensed price no strategy can be called a market edge, and the top reward tier is unreachable by construction rather than by performance.
  • Minutes. Injury impact is a measured lower bound because most players have no measured minutes in any official capture. A better transfer constant applied to a missing input is still missing.
  • A bigger sample. The out-of-sample window is 60 games and the best strategy has 32 graded plays. Every gate that depends on sample size says so, and none can be argued past.
  • A pre-registered rule. A scoreboard whose promotion rule can be edited after seeing results measures the editor. The rule has to exist in writing before the first ranking is published.
