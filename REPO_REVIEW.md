Two of these checks did not exist in the repository and were added this session, because the
existing static checker could not see pages whose tables are built in the browser:

- `scripts/check_links.py` was parsing the contents of `<script>` blocks as markup, so every
  JavaScript template literal was reported as a broken link and a ragged table row. It reported
  1 broken link and 11 unsourced rows that did not exist. It now strips script and style bodies

- `scripts/check_rendered.py` is new. It runs each page's own script against the real data files
  in a small DOM shim and then applies the project's rules to the *output*: one official link per
  rendered row, no page stuck on a loading state, no `undefined`/`NaN`/`[object Object]` cells.
  This is what caught R13 and the `[object Object]` in the parameter table.

## 4. Irregularities found

Each is also published on the site's **Flagged for Review** page under the id given, with the
official source link for the item.

### I1 — Two labs, one repository, no shared navigation (R10, MEDIUM)

A reviewer landing on the root dashboard could not discover the second build at `docs/b/` at all.
**Action:** this session added a three-way switch. The root `index.html` sidebar, Build B's header
nav and the Command Center sidebar all link to each other, and the root page carries a banner
saying its slate is frozen at 13 November. Build A's pages were not otherwise modified.

### I2 — Build A quotes a window it no longer covers (R11, LOW)

Build A is a hand-authored snapshot from the 13 November cut: 31 games over Nov 13–16, a 12:00 PM
ET snapshot and a 5:15 PM ET injury report. Those were true when written and are not current.
**Action:** rather than rewrite another session's pages, `scripts/build_site.py` now injects a
dated "frozen snapshot" banner into every page it generates, and the root page carries an
equivalent banner. The banner is idempotent, so repeated builds cannot stack it.

### I3 — The refresh pipeline has never run end to end (R01, MEDIUM)

`engine/fetch_official.py` was written to re-fetch the official pages inside GitHub Actions. It has
never been executed against a live site by its own code path, and this session's data came from
the web-fetch channel plus a transcription script (`scripts_refresh/`), not from that fetcher.

What the probe settles: a GitHub-hosted runner in this repository reached
`nba.com/stats/teams/advanced`, `/stats/players/traditional`, `/schedule`, `/games?date=2026-11-13`,
a game page, the official injury index and the 11/13 injury PDF, all HTTP 200, at
2026-11-14T00:58:11Z. **The network is not the obstacle.** What is unproven is the parsers.

This session attempted to dispatch the refresh workflow to close the question and was refused:
`HTTP 403: Resource not accessible by integration`. The token can read workflow runs but not start
them. That is recorded rather than worked around.

A second finding from the same probe: it asked for
`Injury-Report_2026-11-14_12_00PM.pdf` and received HTTP 403, and a direct read of the official
index lists **no 11/14 edition at all**. No newer report exists to fetch. That is a data condition,
not a defect, and the site says so where it matters.

### I4 — No market price anywhere; the "reference line" is internal (R04, MEDIUM)

Every economic gate compares the model against a naive line built from the same official inputs.
It measures whether the model's refinements bite, not whether they beat a book. A "+3.0 edge" can
be entirely an artefact of the reference being naive.
**Action:** stated on the Validation page and in the executive verdict; the fix is suggestion S01.

### I5 — Minutes are known for 50 of 465 players (R03, MEDIUM)

The official player table publishes 465 rows across 10 pages, but only page 1 is rendered in the
HTML a plain fetch can read. Every injury impact therefore counts unknown players as 0.00 and is a
**lower bound**. In practice this makes the team-level impact table almost empty: on this edition no
listed player is inside the top-50 table, so every computable impact is 0.00 — which means "unknown",
not "no loss".
**Action:** the injuries page shows the minutes-coverage percentage beside every impact figure and
prints an explicit note when no impact row can be computed, rather than showing a zero.

### I6 — Ten strategies, three different reasons for a zero (R06, MEDIUM)

Six strategies produced graded plays (S1 23, S10 19, S3 14, S5 12, S2 10, S9 7); four produced none,
and not for the same reason:

| Strategy | `n_graded` | `gradeable` | Upcoming picks | Why zero |
| --- | --- | --- | --- | --- |
| S4 Pace-driven total | 0 | true | 0 | threshold the model never crossed in 51 games |
| S6 Availability shock | 0 | false | 0 | needs archived injury reports |
| S7 Player points prop | 0 | false | 6 | needs player game logs for variance |
| S8 Player PRA combo | 0 | false | 2 | needs player game logs for variance |

An earlier draft of the site said "four strategies generated zero plays" as one statement. That
conflated "no edge" with "cannot measure", and it contradicted `picks.json`, which shows six S7 and
two S8 plays on the current board. Both files were corrected. The Validation page now marks each
strategy gradeable or ungradeable and prints the reason.

### I7 — Signed error columns were labelled as absolute values (R13, MEDIUM)

`backtest.json` stores `err_model_margin`, `err_ref_margin`, `err_model_total` and
`err_ref_total` as **signed** values (actual − predicted). The game-log page described them as
absolute. Read literally, a −40.7 point error looked like a 40.7-point hit, and 28 of the 51 rows
carried a negative "error" a reader would have taken as a good result.

**Action:** the columns now print with their sign and the page states the convention; the row
filter compares magnitudes. **No published metric changed** — the averages were always means of
absolute values and recompute correctly (check 4).

### I8 — A newer injury edition exists than the one quoted (R14, LOW)

The official index lists editions through 11/13 07:45 PM ET; this build is transcribed from the
07:30 PM ET edition. The 19:45 edition was read during this review and every status it showed
agreed with what is stored — Antetokounmpo Available, Mathurin Available, Curry Out, Morant Out,
Smart Out — and its visible 11/14 block listed the same five teams as NOT YET SUBMITTED plus the
same Dallas, Brooklyn and Minnesota entries.

What this review does **not** claim is a cell-by-cell diff of the two PDFs: the extraction channel
returns text in chunks that repeat the header and split tables mid-row, so a mechanical diff would
be unreliable. The injuries page states which edition it quotes and that a later one exists.

### I9 — The refresh script duplicated its own capture log (R15, LOW)

`scripts_refresh/refresh_2026_11_13_t1938.py` appended to `refresh_log` unconditionally, so running
it twice wrote the same capture entry twice; the site then rendered the same capture as two events.
**Action:** the script is now idempotent (one entry per `captured_at_utc`, sorted oldest first) and
the duplicated entry was removed by re-running it.

## 5. What could not be verified, and is therefore blank

These are published as blanks or as explicit "unknown" on the site, never inferred. Each is on the
Flagged for Review page.

1. **No market price exists** for any game or prop, so no ROI, no closing-line value, and no
   true edge can be stated. Every "+x units" figure is against a flat −110 assumption on an
   internally originated line.
2. **No player game logs**, so no prop has a probability attached and no prop strategy can be
   graded. The props page shows baselines and projections only.
3. **Minutes for 415 of 465 players**, so every injury impact is a floor.
4. **No 11/14 injury report**, so eight of eleven 11/14 fixtures could not be checked for
   availability. `NOT YET SUBMITTED` is stored exactly as published.
5. **The 11/07 slate**: five of six games were re-read from `nba.com/games?date=2026-11-07`; the
   sixth was not retrieved and is not claimed. The day count (7 games) matches the official calendar.
6. **The nine 11/13 games were live at the data cut.** Their results are deliberately absent; those
   fixtures feed rest maths only and are not pickable.
7. **No legal, licensing or jurisdictional review exists** for any of this.

## 6. Verdict

The repository is internally consistent: every number published on the site recomputes from the
repository's own data, every rendered table row links to an official source, and both checkers
pass. Nothing here is funded, because no strategy clears the skill gate — the best is 16–7 with an
exact binomial p of 0.093 and a Wilson lower bound of 0.491 against a 0.524 break-even.

The material limits are I4 (no market price), I5 (minutes coverage) and I3 (the pipeline's end-to-end
path is unproven). None of them is a reason to withhold publication; all of them are reasons not to
call any of this profitable.
