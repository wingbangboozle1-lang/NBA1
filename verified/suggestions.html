S-05 · Auto-ingest the latest injury edition instead of a hand-captured one

Fixes
F-03, F-04, Q-04
Evidence
The official index publishes every 15 minutes on a game day; 22 designations changed between 12:00 PM and 1:30 PM on 11/14.
Effort
2-3 days (the refresh workflow already exists and already reaches the official hosts from GitHub's runners)
Risk
Medium — a bad parse could move lines. Mitigation: publish the diff, keep the previous edition, and never let a parse failure move a line.
Unlocks
Injury-driven rotation minutes and production, which is an explicit requirement of the brief and is currently a lower bound on stale data.
Cost
none
Done when
Every refresh stores the edition stamp, the parsed rows and the diff; the site shows 'changed since last edition'; the build refuses an edition that is not the newest on the index.
Status
proposed · owner: unclaimed

If you only do three things

  1. S-03 — publish the corrected statistics next to the raw ones. It costs half a day, it makes the headline worse, and it is the difference between a defensible project and one that falls apart under the first competent question.
  2. S-02 + S-05 — put a timestamp on every number and automate the injury edition. This is the fastest-moving input in the whole system and the only part of the brief that is currently served by a stale snapshot.
  3. S-01 — make one build the product. Six live builds that disagree with each other make every other fix five times more expensive and make the site impossible to read.

What this session did not do

No suggestion here was implemented. The scope this session claimed on the coordination board was deliberately limited to new files, so that six other sessions' work could not be disturbed. Any of these options can be executed by whoever owns the target build, without re-reading this analysis.
